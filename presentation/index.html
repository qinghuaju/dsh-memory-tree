问题 / 02

每次对话，都从零开始

上下文是内存，不是记忆：任务结束，上下文随之清空；下次再讲一遍。

TASK A · 进行中
上下文塞满历史
一切都在，但昂贵、有限、只在这一次。
TASK A · 结束
上下文被清空
会话关闭，经验没有落到任何地方。
TASK B · 新任务
重新解释一遍
偏好、约定、踩过的坑，全部重来。
TASK C · 又一个新任务
再解释一遍
重复劳动，且每次都可能讲得不一致。
上下文窗口解决“这一次”，记忆库解决“下一次”。 CONTEXT IS MEMORY · MEMORY IS AN ASSET
COST
重复解释：偏好与约束每次重讲，token 和耐心都在消耗
DRIFT
答复漂移：没有共同底稿，同一个问题可能给出不同答案
LOSS
经验流失：踩过的坑只存在于这一次的上下文里

结构化 / 06

结构化：让记忆可寻址

Markdown 被解析成一棵 AST 树：每个节点有唯一路径，命中后可以顺着路径回溯上下文。

/光遗传学与生物显示/艺术应用/生物显示/像素化藻类阵列
标题→ section（小节节点）
编号→ section，用于步骤/清单
项目符→ point（要点节点）
段落→ paragraph，默认记忆单元
命中任意节点，都能把它所在的整条路径作为上下文一起召回。

语义 / 07

语义：向量 + 软边，而不是只认关键词

每个节点算一个 1024 维向量；相近的节点之间连一条“软边”，召回时沿边扩散一跳。

07 · 向量化与相似边07 / 14
存储 / 08

存储：热、温、冷三层，按年龄搬家

SQLite 单文件 WAL；整份文档按时间迁移，召回跨层加权，空间不够时可以压缩回收。

hot最近 30 天，召回主力
warm30–180 天，权重 0.9
cold180 天以上，权重 0.78
冷层可以只留文本、丢掉向量：以“精确记忆”换空间；分层文件仍可单独备份。

检索 / 09

检索：混合打分，而不是只看向量

base = ( 0.55·cos + 0.20·lexical + 0.25·RRF ) × tier
向量相似0.55
词法命中0.20
双路一致 RRF0.25
一跳扩散×0.55
先验加分+0.14
最后做多样性收敛（MMR 0.88）与预算裁剪：默认 6 条 / 2400 字符。
TOP-3 · 本次召回
0.81生物显示 / 像素化藻类阵列
0.66装置方案 / 8×8 原型
0.52材料清单 / 培养基与宿主
01两路召回：向量 topK + FTS 关键词 topK（中文 bigram）
02融合排序：相似度为主，词法与 RRF 兜住专有名词
03沿边扩散：父节点与相似邻居各按 0.55 折入
04预算裁剪：先广后精，宁缺毋滥，避免把上下文塞满
WHY
为什么要混合：只看向量时，型号/专有名词容易漏召回
BUDGET
预算：默认 6 条 / 2400 字符，超出即裁剪
DIVERSITY
收敛：MMR 0.88，避免同一段话的多个副本

注入 / 10

注入：把记忆放回上下文

每轮第一步，按当前问题召回一次，作为一条独立消息插入；记忆是参考，不是指令。

USER继续做上次那个绿藻显示装置，材料清单帮我列一下
PLUGIN · <memory-recall>/光遗传学与生物显示/装置方案
需求：像素化藻类阵列 · 光照序列驱动
约定：先做 8×8 原型，电源用 5V USB
ASSISTANT沿用上次的 8×8 方案，清单按“藻类培养基 / 光源阵列 / 控制板 / 遮光结构”四组给出……
只插一条不修改用户原话，不重复注入，同一轮只做一次
冷却 60s避免连续追问时反复召回、拖慢首字延迟
帧标记转义记忆内容里的标签会被转义，不能被当成本轮指令
注明不可信召回块明确标注“历史参考资料”，以当前请求为准

工程 / 11

工程保障：记忆不能拖垮对话

01进程隔离：SQLite / 向量 / AST 全部在子进程，宿主只留薄适配
02崩溃自愈：子进程死了，对话继续；请求干净失败，后台指数退避重启
03关闭预算：1 秒硬上限，SIGKILL 引擎，不扣住宿主退出
04现场可查：plugin.log 记录挂载、重启、stderr 与引擎告警
最坏情况是“暂时记不住”，不是“没法聊”。
ISOLATION
崩溃隔离：SIGKILL 子进程，宿主存活并自动恢复（8/8）
SHUTDOWN
关闭实测：17ms；硬上限 1s，不扣住宿主退出
LOG
现场可查：plugin.log 512KB 轮转，含子进程 stderr

使用 / 13

使用：一条命令装好，几个工具够用

$ node scripts/install.mjs --profile ~/.dsh/profiles/desktop ✓ cordis.patch.yml 已写入（幂等，重复执行安全） ✓ 插件入口：dsh-memory-tree.plugin.mjs $ node scripts/demo.mjs docs=570 nodes=65160 · 3 tiers · p50 12ms/1k $ mem_stats # 文档 / 节点 / 分层 / 占用 $ mem_recall # 语义 + 词法混合检索 $ mem_store # 显式记一条长期记忆
mem_recall按问题召回，返回带路径的片段
mem_store把结论/偏好写成长期记忆
mem_stats规模、分层、占用、待嵌入
mem_dream去重、重建软边、合并主题
mem_rotate手动触发热/温/冷轮转
数据一个目录：~/.dsh/memory-tree/
配置config.json 机器级共享，插件参数只覆盖显式字段
卸载删插件条目即可；记忆数据保留，可随时重装
安装器幂等；profile 会备份，误操作可回滚。
